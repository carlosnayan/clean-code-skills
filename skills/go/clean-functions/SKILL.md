# Clean Functions

## F1: Too Many Arguments (Maximum 3)

```go
// Bad - too many parameters
func CreateUser(
	name string,
	email string,
	age int,
	country string,
	timezone string,
	language string,
	newsletter bool,
) (User, error) {
	// ...
}

// Good - use a struct
type UserData struct {
	Name       string
	Email      string
	Age        int
	Country    string
	Timezone   string
	Language   string
	Newsletter bool
}

func CreateUser(data UserData) (User, error) {
	// ...
}
```

More than 3 arguments means your function is doing too much or needs
a data structure. A leading `ctx context.Context` doesn't count toward the limit.

## F2: No Output Arguments

Don't modify arguments as side effects. Return values instead.

```go
type Report struct {
	Content string
}

// Bad - modifies the caller's value
func AppendFooter(report *Report) {
	report.Content += "\n---\nGenerated by System"
}

// Good - returns a new value
func WithFooter(report Report) Report {
	report.Content += "\n---\nGenerated by System"
	return report
}
```

The same applies to slices and maps: prefer returning a new slice over appending
into one the caller owns.

## F3: No Flag Arguments

Boolean flags mean your function does at least two things.

```go
// Bad - function does two different things
func Render(isTest bool) string {
	if isTest {
		return renderTestPage()
	}
	return renderProductionPage()
}

// Good - split into two functions
func RenderTestPage() string       { ... }
func RenderProductionPage() string { ... }
```

## F4: Delete Dead Functions

If it's not called, delete it. No "just in case" code. Git preserves history.
Run `go vet ./...` and a linter with `unused` enabled to find them.

## F5: Never Ignore Returned Errors

A discarded error is a hidden bug. Handle it, wrap it, or state in a comment why
ignoring it is safe.

```go
// Bad - failure disappears
_ = file.Close()

// Good - the failure reaches the caller
if err := file.Close(); err != nil {
	return fmt.Errorf("closing report file: %w", err)
}
```

## F6: Return Early, Don't Nest

Go's error handling rewards guard clauses. Keep the happy path at the left margin.

```go
// Bad
func Process(id string) (Result, error) {
	if id != "" {
		record, err := load(id)
		if err == nil {
			return transform(record), nil
		}
		return Result{}, err
	}
	return Result{}, ErrEmptyID
}

// Good
func Process(id string) (Result, error) {
	if id == "" {
		return Result{}, ErrEmptyID
	}

	record, err := load(id)
	if err != nil {
		return Result{}, fmt.Errorf("loading %s: %w", id, err)
	}
	return transform(record), nil
}
```
